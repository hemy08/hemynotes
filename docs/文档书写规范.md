# 文档书写规范

## 概述

本文档规定了知识库文档的书写规范，以**项目为粒度**组织文档结构。一个项目是一个完整的知识体系，包含相关的子模块、具体内容和配套资源。

## 项目结构规范

### 项目定义

**项目**：具有独立知识体系的主题领域，如"计算机"、"数学"、"物理"等。

**示例项目：010-计算机**

```
docs/
└── 010-计算机/                          # 项目根目录
    ├── 000_导读.md                       # 项目导读（索引文件）
    ├── images/                           # 项目级共享图片
    │   └── 20240517204539.png
    │
    ├── 010_计算机基础/                   # 模块目录（一级模块）
    │   ├── 000_导读.md                   # 模块导读
    │   ├── 010_计算机发展历程/           # 子模块目录（二级模块）
    │   │   ├── 000-导读.md               # 子模块导读
    │   │   ├── images/                   # 子模块图片
    │   │   ├── 001-史前计算机时代.md     # 内容文件
    │   │   ├── 002-机械式计算机时代.md
    │   │   └── ...
    │   ├── 020_计算机的分类与发展方向/
    │   ├── 040_计算机工作过程/
    │   └── ...
    │
    ├── 020_计算机组成原理/               # 模块目录
    │   ├── 000_导读.md
    │   ├── images/
    │   ├── 001-控制器.md                 # 直接包含内容文件
    │   ├── 002-存储器.md
    │   └── ...
    │
    └── 030_计算机系统/                   # 模块目录
        └── ...
```

### 项目结构说明

| 组件 | 命名规则 | 作用 | 示例 |
|------|----------|------|------|
| 项目根目录 | `NNN-项目名称` | 项目根目录，包含所有相关内容 | `010-计算机` |
| 项目导读 | `000_导读.md` | 项目索引，描述知识体系、目录结构 | `010-计算机/000_导读.md` |
| 项目图片 | `images/` | 项目级共享图片资源 | `010-计算机/images/` |
| 模块目录 | `NNN_模块名称` | 一级模块，可包含子模块或内容 | `010_计算机基础` |
| 模块导读 | `000_导读.md` 或 `000-导读.md` | 模块索引，列出子模块或内容 | `010_计算机基础/000_导读.md` |
| 子模块目录 | `NNN_子模块名称` | 二级模块，通常包含具体内容 | `010_计算机发展历程` |
| 内容文件 | `NNN-标题.md` | 具体知识内容文档 | `001-史前计算机时代.md` |
| 模块图片 | `images/` | 模块级图片资源 | `010_计算机发展历程/images/` |

### 编号规则

#### 项目编号

- **格式**：三位数字 `NNN`
- **范围**：010-999
- **间隔**：建议以10为间隔，预留扩展空间。目录从100开始，每次加10，文件名从010开始，每次加1
- **示例**：`010-计算机`、`020-数学`、`030-物理`

#### 模块编号

- **格式**：三位数字 `NNN`
- **范围**：010-990
- **间隔**：建议以10为间隔，目录从100开始，每次加10，文件名从010开始，每次加1
- **示例**：
  - `010_计算机基础`
  - `020_计算机组成原理`
  - `030_计算机系统`

#### 内容编号

- **格式**：三位数字 `NNN`
- **范围**：
  - `000`：导读/索引文件
  - `001-999`：具体内容文件
- **示例**：
  - `000-导读.md`（导读）
  - `001-史前计算机时代.md`（内容）

#### 子模块编号

- **格式**：三位数字 `NNN`
- **范围**：010-990
- **间隔**：建议以10为间隔，目录从100开始，每次加10，文件名从010开始，每次加1
- **示例**：
  - `010_计算机发展历程`
  - `020_计算机的分类与发展方向`

### 代码块

**代码块规范**：代码块(\`\`\`)仅用于展示**可执行的代码**或**配置文件内容**,不用于纯文字描述。

**正确使用**：

```markdown
**Python代码示例**：

```python
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + middle + quick_sort(right)
```

**JSON配置示例**：

```json
{
    "name": "my-project",
    "version": "1.0.0",
    "dependencies": {
        "numpy": "^1.20.0"
    }
}
```

**Shell命令示例**：

```bash
# 编译C程序

# 运行程序
./program
```
```

**错误使用（禁止）**：

```markdown
❌ 错误：使用代码块展示纯文字描述

```text
这是一个文字描述，不应该使用代码块。
代码块应该只用于代码。
```

❌ 错误：使用代码块展示算法步骤

```
步骤1: 初始化数组
步骤2: 遍历元素
步骤3: 比较并交换
```

❌ 错误：使用代码块展示列表内容

```
- 项目1
- 项目2
- 项目3
```
```

**正确替代方案**：

对于非代码内容,应使用以下方式：

**1. 普通文本描述**：

```markdown
算法步骤如下：

1. 初始化数组
2. 遍历元素
3. 比较并交换
```

**2. 使用表格**：

```markdown
| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 初始化 | 设置初始值 |
| 2 | 遍历 | 循环处理 |
| 3 | 比较 | 判断条件 |
```

**3. 使用引用块**：

```markdown
> 算法说明：该算法采用分治策略，时间复杂度为O(n log n)。
```

**4. 使用Admonition提示框**：

```markdown
!!! note "重要说明"
    这是重要的文字说明内容，使用提示框展示更加清晰。
```

**5. 使用HTML样式**：

```markdown
<div style="background-color: #FFF3E0; padding: 15px; margin: 10px 0; border-left: 4px solid #FF9800;">
    <strong>算法步骤</strong>
    <ol style="margin: 5px 0;">
        <li>初始化数组</li>
        <li>遍历元素</li>
        <li>比较并交换</li>
    </ol>
</div>
```

**代码块适用范围**：

| 适用 | 不适用 |
|------|--------|
| 编程语言代码(C, C++, Python, Java等) | 纯文字描述 |
| 配置文件(JSON, YAML, XML, INI等) | 算法步骤列表 |
| Shell/终端命令 | 普通段落文本 |

### 标签页（Tabs）

MkDocs Material 支持标签页功能，用于展示同一内容的不同版本，如不同语言实现、不同方式等。

**基本语法**：

```markdown
=== "标签1"

   - 遵循统一的布局模式

### 减少HTML使用规范

为了保持文档的简洁性和可移植性，应尽量减少或避免使用HTML标签。优先使用纯Markdown语法和Mermaid图表。

#### HTML使用原则

| 推荐程度 | 使用场景 | 示例 |
|----------|----------|------|
| ✅ 强烈推荐 | 仅时间戳样式 | `<span style="...">最后更新：xxx</span>` |
| ❌ 不推荐 | 布局和样式控制 | `<div style="background: #F5F5F5; padding: 20px;">` |
| ❌ 避免使用 | 复杂表格布局 | `<table><tr><td>...</td></tr></table>` |
| ❌ 避免使用 | 内联样式 | `<span style="color: red;">` |

#### Markdown替代方案

**1. 背景色块 → 使用admonition**

❌ 不推荐（使用HTML）：
```html
<div style="background-color: #F5F5F5; padding: 20px; margin: 10px 0; border-radius: 8px;">
    容器内容
</div>
```

✅ 推荐（使用admonition）：
```markdown
!!! note "标题"
    容器内容
```

**2. 颜色强调 → 使用admonition类型**

❌ 不推荐：
```html
<span style="color: #F44336; font-weight: bold;">重要内容</span>
```

✅ 推荐：
```markdown
!!! warning "重要内容"
```

或使用四色标签：

| 标签 | 语法 | 颜色 |
|------|------|------|
| 蓝色 | `span style="color:rgb(100,180,246)"` | 🔵 信息 |
| 绿色 | `span style="color:rgb(76,175,80)"` | 🟢 成功 |
| 橙色 | `span style="color:rgb(255,152,0)"` | 🟠 警告 |
| 红色 | `span style="color:rgb(244,67,54)"` | 🔴 错误 |

**3. 数据结构可视化 → 使用Mermaid**

❌ 不推荐（使用HTML表格）：
```html
<table>
    <tr><td>节点1</td><td>节点2</td></tr>
</table>
```

✅ 推荐（使用Mermaid graph）：
```mermaid
graph LR
    A["节点1"] --> B["节点2"]
```

❌ 不推荐（使用ASCII艺术）：
```text
┌───────┐     ┌───────┐
│  10   │ ──→ │  20   │
└───────┘     └───────┘
```

✅ 推荐（使用Mermaid）：
```mermaid
graph LR
    A["10"] --> B["20"]
```

**4. 代码块内注释 → 使用标准注释语法**

❌ 不推荐：
```html
<code style="background: white; padding: 2px 8px;">push(1)</code>
```

✅ 推荐：
```markdown
`push(1)`
```

## ASCII图处理规范

### 问题说明

ASCII图（如使用`┌─┐│└─┘╔═╗║╚═╝`或`/\|`绘制的树形结构、流程框图）存在以下问题：

| 问题 | 影响 |
|------|------|
| 可读性差 | 字符拼接的图形难以阅读 |
| 维护困难 | 修改时需要重新对齐所有字符 |
| 样式单一 | 无法添加颜色、强调等视觉效果 |
| 响应式差 | 不同宽度下可能显示错乱 |

### 处理原则

**禁止**：在Markdown文档中使用ASCII字符绘制图形

**替代方案**：

1. **树形结构** → 使用 `graph TB` Mermaid流程图
2. **对比表格** → 使用 Markdown表格
3. **流程框图** → 使用 `flowchart TB/LR` Mermaid流程图
4. **说明性框图** → 使用 MkDocs Admonition 或 HTML样式

### 树形结构转换示例

**ASCII树（禁止）**：

```text
        30
       /  \
      20   40
     /  \    \
    10  25   50
```

**Mermaid图（推荐）**：

```markdown
```mermaid
graph TB
    30((30)) --> 20((20))
    30 --> 40((40))
    20 --> 10((10))
    20 --> 25((25))
    40 --> 50((50))
    
    style 30 fill:#E3F2FD
    style 20 fill:#E8F5E9
    style 40 fill:#E8F5E9
```
```

## 代码块使用规范

### 基本原则

**代码块（\`\`\`）仅用于**：
- 可执行的代码（Python、C、C++、Java等）
- 配置文件内容（JSON、YAML、XML等）
- Shell命令

**代码块禁止用于**：
- 纯文字描述
- 算法步骤列表
- 公式或数学推导（应用LaTeX公式）

### 文字描述处理

对于文字描述内容，使用以下方式：

| 内容类型 | 推荐格式 |
|----------|----------|
| 普通文本 | 直接书写，不使用代码块 |
| 列表 | Markdown列表（`-` 或 `1.`） |
| 说明性文本 | Admonition提示框 |
| 步骤列表 | Markdown表格或有序列表 |

### 数学公式规范

**数学公式必须使用LaTeX格式**：

- **行内公式**：使用 `$formula$` 格式
- **行间公式**：使用 `$$formula$$` 格式（两端需加换行）

| 场景 | 格式 | 示例 |
|------|------|------|
| 行内公式 | $E=mc^2$ | 能量公式 $E=mc^2$ |
| 行间公式 | $$h \leq 1.44 \times \log_2(n+2)$$ | 高度上界 $$\int_{-\infty}^{\infty} e^{-x^2} dx = \sqrt{\pi}$$ |

!!! warning "注意"
    不要在代码块中使用LaTeX公式，应使用行内或行间公式语法。

### 示例对比

**错误用法**：

````markdown
```text
算法复杂度: O(n log n)
高度上界: h ≤ 1.44 × log₂(n+2)
```
````

**正确用法**：

```markdown
算法复杂度: $O(n \log n)$

高度上界:
$$h \leq 1.44 \times \log_2(n+2)$$
```
